推荐理由

今天选 Agentic ESOpt，它推进的是一个很根子的东西：训练大模型 agent，到底非得靠"反向传播"吗？ 它把一个被冷落了近十年的老办法——进化策略（Evolution Strategies，简称 ES）——在"训练长程大模型 agent"这个新战场上重新擦亮，并给出了 ES 什么时候真的比强化学习（RL）更强的清晰证据。

  • 它推进了什么一条不用反向传播的全参数后训练路线。反向传播要把模型答题的整个中间过程都存在显存里、再一层层往回算梯度；ES 彻底不这么干，只需要"让模型把任务跑一遍、打个分"，因此全参微调 27B 只吃 8.41GB 显存，比 RL(GRPO) 的 58.88GB 省了 85.7%。更妙的是它天生不怕长任务链——RL 在长链条上会因"归因变糊 + 显存爆炸"崩掉，而 ES 只看"这一整趟最后得几分"，链条再长也不受影响。
  • 命中的质量信号HuggingFace Daily Papers 当日 #1，89 赞（明显甩开第 2 名的 85 赞，第 3 名断崖到 51）；作者阵容里有 Yee Whye Teh（牛津/Google DeepMind）和 Wee Sun Lee（NUS） 两位顶级机器学习学者；代码开源、被 alphaXiv 精选。这不是刷分应用，是一篇方法/范式论文。
  • 对思染追前沿的价值一是认知——"训练大模型不一定要反向传播"这件事，会改写你对"模型怎么变强"的底层地图；二是直接可用——你平时优化京小贝的提示词/skill，本质就是在做 ES，这篇给了这套"人肉进化"一个正规骨架；三是双重相关：ESOpt 明确说它能和"进化提示词/skill"一起协同优化，而今天 HF 第 2 名恰好是《Demystifying Agent Skills》（讲 skill 到底为什么有用、什么时候失效），两篇合起来正好覆盖一个 agent 的两个旋钮——权重与提示。

诚实交代：它不是万金油，提升幅度是"任务越长、模型越弱"才明显；且 test-time 要跑很多遍评测、比较贵（作者自己列为局限）。信号上 S2（Semantic Scholar）今天限流没取到早期引用数，但发表才 2 天，引用≈0 本属正常，HF#1 + 顶级署名 + 开源已足够。

七拍故事

1｜主角：一个要"练"长程 agent 的人，手里只有一张普通显卡

主角是任何想把一个大模型 agent 练得更强的人。这里的 "agent" 指：模型不是答一句就完，而是要连着做很多步——比如"帮我在这个网站上一步步点，最后订到票"，要点击、翻页、填表几十次才算完成一趟。这一整趟叫一条 trajectory（轨迹），"要走多少步才结束"叫 horizon（横线/时间跨度），横线越长，任务越"长程（long-horizon）"。

他想让模型在这类长任务上更靠谱，就得训练它。问题是：模型很大（几十亿参数），任务很长（几十步），他的显卡装不下。

2｜困境：主流的训练法（RL），在"长任务 + 大模型"这里同时踩两个雷

现在训练大模型 agent 的主流叫 RL（Reinforcement Learning，强化学习）——具体是 PPO、GRPO、DAPO 这些名字的方法。它的引擎是 反向传播（backpropagation）。反向传播这四个字要拆开讲清楚：

模型答完一题，系统拿"答对/答错、得几分"这个结果，从最后一步一层一层往回算——算出"当初每一个参数该往哪个方向、挪多少，才能让下次更容易答对"，然后照这个方向把参数挪一小步。要能往回算，就必须把答题时中间每一步的运算结果全都存在显存里（这些中间结果叫 激活值 / activation）。

放到"长任务 + 大模型"上，这套引擎同时踩两个雷：

  • 雷一：显存爆炸。 任务有几十步，就得把这几十步的全过程都存下来才能往回算，显存瞬间不够。所以想全参数（每个参数都动）微调一个大模型，几乎不可能。
  • 雷二：归因变糊（credit assignment，功过分配）。 一整趟几十步，最后成没成——到底是第 3 步点对了、还是第 27 步填错了？RL 要把"最后那一个总分"摊回到中间每一步、每个参数头上。链条越长，这个"摊"就越糊、越不准，模型越学不到东西。

一句话：横线越长，RL 的这两个雷踩得越深。

3｜旧路：要么只改嘴（提示词），要么硬扛反向传播

面对这堵墙，之前大体两条路。一条是根本不训模型本体、只在外面改提示词/skill（便宜，但模型的"底子"没变强，天花板有限）。另一条是硬扛反向传播，用各种省显存的工程手段（比如只微调一小块参数、梯度检查点）勉强训——但要么改不动大模型的全部参数、要么在长任务上被"归因变糊"拖垮。两条路都没真正解决"想全参数地、在长任务上把大模型练强，但显卡又不够"这个核心矛盾。

4｜转折：换个引擎——不往回算，靠"抖一群副本、比个分"

作者的关键转念是：既然"往回算梯度"这件事本身就是万恶之源（既要存全过程又要摊归因），那能不能压根不往回算？

于是他们捡回一个老办法——进化策略（Evolution Strategies）。它的思路可以完全用日常话讲透（这就是全篇最该记住的那个画面）：

你手上有一份当前模型（一堆参数）。你复制出 8 个"分身"，每个分身都随机抖一抖——给每个参数加一点点随机噪声（像给同一个人做 8 个略有差别的版本）。让这 8 个分身各自把整条长任务从头到尾跑一遍，各自拿回一个总分（订到票=高分、没订到=低分）。然后你看谁分高：把"分高的那些分身当初抖动的方向"加权平均起来，就是"往这边挪能变好"的方向；照这个方向，把原模型整体挪一小步。分越高的分身，它那一抖的方向权重越大。抖完、挪完，再来一轮。

就这么简单——抖一群副本 → 各自跑一遍打分 → 留住得分高的方向 → 挪一小步 → 重复。整个过程里，你对模型做的唯一动作是"让它把任务跑一遍、看得几分"，这跟平时让模型答题（推理）一模一样，用的是同一份显存。你从来不需要存中间过程、从来不需要往回算梯度。

这一转，两个雷同时拆了：

  • 显存雷拆了只用推理级显存，全参数微调 27B 只要 8.41GB。
  • 归因雷拆了ES 只看"这一整趟最后得几分"，把功过直接算在"这一整套抖动"头上（叫 trajectory-level attribution，轨迹级归因），根本不去摊到每一步。所以横线再长，它也不糊。

5｜解法：Agentic ESOpt 的三件关键设计

作者把这套思路做成一个能用的框架 Agentic ESOpt，几个设计选择值得点名：

  1. 加权更新怎么算（把上面那段落成公式的直觉）：一轮里采 G 个抖动版本（种群大小 G：WebArena 任务 G=8、数学/DocVQA G=16、数独 G=32），每个拿回奖励 R。先把这一批 R 做标准化（z-score，减均值除标准差）——这样不管这批分数整体偏高偏低，都只看"谁相对更好"，避免被极端分带偏。然后按"标准化后的分"给每个抖动方向加权、求平均，就是这一步要挪的方向。
  2. 抖动幅度会自己变抖动幅度 σ（sigma）一开始大（放开手脚探索，别一上来就钻牛角尖），按余弦曲线（cosine decay）慢慢收小（后期精修、别再乱跳）。训练时 σ 收到一个非零小值当"正则"（保持一点探索），test-time 直接收到 0（只求最优、不再探索）。
  3. 省显存的小技巧不真的把 8 份抖动向量都存下来（那也很占空间），而是只存生成这些随机抖动用的"随机种子"（seed）——需要时用种子重新生成同一份抖动。这样连抖动本身都几乎不占额外空间。
  4. 黑盒 = 能和"改提示词/skill"拼在一起：ES 只要一个分数、不管模型内部怎么算，是黑盒优化。所以它能跟同样"只看分数"的提示词/skill 进化拼在一个循环里，同时进化参数和提示（作者叫 parameter–context co-evolution，参数-上下文协同进化）。

6｜结局：省 85.7% 显存拿到更好成绩，还有一个漂亮的"横线交叉"反直觉发现

硬战果（都基于开源的 Qwen3.5 系列）：

  • WebArena-Lite（模拟真实网页操作的 agent 基准）：Qwen3.5-27B 全参微调，No-Skill 基线 29.47 → 36.16（+6.69）；配合 skill 检索（Trace2Skill）从 33.94 → 36.36。
  • 数独（15 步长任务）/ 数学 / DocVQA（Qwen3.5-4B）：数独上 ESOpt 53.13，比最强的 GRPO(40.63) 高 12.5 个点；数学/DocVQA 比基座模型 +13.8、比 GRPO 平均高 8.3。
  • 显存ESOpt 8.41GB vs GRPO 58.88GB，省 85.7%——而且是全参数微调。
  • test-time 自动设计启发式（AHD）：让它在解题当场同时进化提示和参数，36 个"方法×预算"设置里赢了 28 个。

最反直觉的副发现——"横线交叉"（horizon crossover），全篇最精彩的一笔：作者把同一个任务的横线长度（要走几步才结束）从 5 步、10 步拉到 15 步，看谁最强：

  • 横线 H=5（短）：PPO（一种 RL）最强，90.63%。
  • 横线 H=10（中）：GRPO（另一种 RL）最强，67.71%。
  • 横线 H=15（长）：Agentic ESOpt 反超，53.13%（同题 GRPO 只有 40.63%）。

这条曲线推翻了一个默认信仰——"用梯度的 RL 应该永远比参数空间瞎搜索强"。不是永远，是分场景，而且分界线正好是横线长度：链条越长，RL 的"归因变糊"越致命，ES 的"只看总分、不怕长链条"越占便宜，两条线在某个横线长度上交叉。ES 不是全面更好，是选对了战场。

7｜内核

训练一个大模型，不一定非得反向传播。 当任务变成"长程、只有最后才知道成败、还想动很大的模型"时，"抖出一群变异副本、各自跑一遍比分、留住得分高的方向"这种老派、省显存、天生不怕长链条的办法，可能反超主流的 RL。省的不是一点半点（显存 85.7%），换来的是"用普通机器全参微调大 agent"这件以前做不到的事——代价是你得能便宜地、大量地给它打分。

来龙去脉（倒读 3 层）

  • 第 1 层——它在挑战谁当下大模型 agent 后训练的主流是 RL 家族（PPO → GRPO → DAPO），全靠反向传播 + 把总奖励摊回每一步。ESOpt 直接质疑："长程 agent 这个特定场景，这条主流路是不是走错了？"并用"横线交叉"给出证据：过了某个横线长度，RL 就该让位。
  • 第 2 层——这条线正在升温ESOpt 不是孤例。2026 年冒出一整股"用进化/ES 给 LLM agent 做后训练"的新苗：《Cooperative Coevolution for Resource-Constrained Agentic LLM Post-Training》(arXiv:2608.02391，同样指出 agent 的长多轮轨迹让梯度后训练太吃显存、ES 省内存)、立场文《Position: Agentic Evolution is the Path to Evolving LLMs》(arXiv:2602.00359)。ESOpt 是其中把"ES vs RL 全参数正面刚、并给出横线交叉硬证据"做得最干净的一篇。它也和本台账里"自我进化 / 黑盒优化"这条暗线相接（[[2026-06-09--openskill|OpenSkill 自我进化]]、[[2026-06-21--fapo-autonomous-prompt-optimization|FAPO 自动进化提示词]]、[[2026-08-19--large-discovery-models|LDM 生成器+校准评估脑]]）。
  • 第 3 层——根再往下就是 2017 年 OpenAI 的《Evolution Strategies as a Scalable Alternative to Reinforcement Learning》(arXiv:1703.03864)——十年前就证明"抖参数比分选优"在打游戏、机器人控制上能跟 RL 掰手腕、还特别好并行，但大模型时代被反向传播+RL 的锋芒盖过、冷了近十年。更根上，是强化学习永恒的两难：探索（explore）vs 归因（credit assignment）——长横线下"把最终结果的功过分配到中间每一步"这堵墙，是整条线一直想绕开的东西。ESOpt 的答案是：干脆不分配，只看总分。

与今日 HF #2 的呼应（值得单独记一笔）：今天第 2 名是《Demystifying Agent Skills: Why They Work—Until They Don't》(arXiv:2608.14036)。它独立发现：agent 的 skill 主要是当"程序锚点"稳住动作（占 65.7%），而不是灌进缺失的知识（只占 4.5%）；而且 skill 库一大，检索精度就崩——候选池从 5 个涨到 100 个，真正用对的精度从 29.6% 掉到 3.3%。两篇合看非常完整：一个 agent 有两个可调的旋钮——权重（ESOpt 管）和提示/skill（skills 论文管），而 ESOpt 恰恰主张这两个旋钮能放进同一个进化循环里一起拧。

对思染：模型进化 & 怎么用

模型进化逻辑往哪挪了一步前沿多出一条"训练范式"的岔路——训练大模型不一定要反向传播。当目标是"长程、稀疏奖励、还想动很大的模型"，黑盒的"抖一群副本比分选优"可能反超梯度 RL。这意味着两件事同时发生：训练范式在多元化（不再只有一条反向传播路），以及训练大 agent 的显存成本被打下来（全参微调 27B 从 ~59GB 降到 ~8GB）。

怎么用（提示词 & 认知）

  1. 你优化提示词/skill，本质就是在做 ES——把它做规范。 你手上几个提示/skill 变体，各自跑一批真实 query 打分，留住得分高的方向，小步迭代、幅度先大后小——这就是进化策略。这篇给了这套"人肉进化"一个数学骨架，也点破一个要害：ES 的一切都吊在那个"分数"上。所以优化提示词时，把评测集（reward）做扎实、做得能便宜大量地跑，比纠结"这句怎么改"更重要——评分不准，再多轮迭代都在往错方向进化。
  2. 别把"改模型"和"改提示/skill"当两件割裂的事。 ESOpt 证明参数和提示能在同一个循环里协同进化。产品上：京小贝的模型微调节奏和 prompt/skill 迭代节奏，可以设计成一套"同一个评测集驱动"的联动闭环，而不是两拨人各调各的。
  3. 成本账是真的全参微调 27B 只要 8.4GB、省 85.7% 显存——意味着"用小得多的机器、去全参微调更大的模型来干长程任务"变得可行。对预算/显存受限、又想上 agentic 能力的团队，这是一条真实的降本路径。前提是：你得能便宜地大量跑评测（ES 要反复让分身跑任务打分），所以它偏爱"评测便宜、能自动打分"的场景。
  4. 认知锚以后看到任何"训练方法"，多问一句——它是反向传播（要存全过程、怕长链条、改大模型贵、需要梯度）还是黑盒打分（省显存、不怕长链条、改多大模型都行、但要能大量便宜地评分）？两条路各有战场，横线越长越偏向后者。

诚实的边界（作者自列局限）：① 引入新超参——种群大小 G 怎么随模型规模调，还没定论（初步迹象是模型越强、需要的抖动样本越少）；② test-time 评估很贵（要跑很多遍才知道谁分高）；③ 持续学习（continual learning，边用边学不遗忘）下行不行还不清楚；④ 提升幅度是"任务越长、模型越弱"才显著，本就强的短任务它不占优。所以这是一把在特定战场（长程、稀疏奖励、显存受限）非常锋利的刀，不是取代 RL 的银弹。
