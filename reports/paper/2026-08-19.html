推荐理由

今天选 UCL Jun Wang 组的 Large Discovery Model（LDM，大发现模型），理由三条：

  1. 它推进的能力前沿是"发现"本身——不是"把已知问题答得更好"，而是"在molecule（分子）、protein（蛋白质序列）、program（程序）这类无边无际的可能空间里，高效搜出人和老办法找不到的好东西"。台账里的自主研究智能体（[[2026-06-12--arbor-htr|Arbor]]、[[2026-07-27--arex-rsi-deep-research|AREX]]）是"编排一堆智能体走流程"；LDM 不一样，它去修模型本身的一个根子毛病：大模型很会生成点子，但让它给自己的点子打分、说"我有多确定"，尤其对它没见过的新点子，它经常胡乱自信。LDM 把这颗坏掉的"自评脑"换成一个会诚实说"我心里没底"的独立评估器。这是机理层的补丁，不是流程层的拼装。
  2. 质量信号HuggingFace Daily Papers 上 47 赞、排在 08-18 窗口第 3 位（社区每天投票筛过的重要论文榜）；作者是 UCL 的 Jun Wang 组——做多智能体强化学习、LLM 智能体的老牌实验室；三个真实领域（神经网络训练、抗体设计、分子优化）都拿到硬结果。诚实交底：这是发表 3 天的预印本，还没有会议接收，Semantic Scholar 也还没收录（引用≈0 是正常的），所以我不是靠引用选它，是靠"方向 + 机理 + 社区热度"。
  3. 对思染的价值LDM 的核心心法——"别信生成器对自己的打包票，给它配一个会报告'我有多确定'的独立打分器，再按'可能好 + 我没底'去花昂贵的真实测试预算"——几乎是照着京小贝这类信贷风控产品的痛点写的。它同时是一把"模型正往哪进化"的认知锚。

七拍故事

1｜主角

主角是一台想当"发现引擎"的大模型。

它面对的活儿叫"discovery（发现）"：给定一个又贵又慢才能验证好坏的目标（比如"这个分子药效好不好""这套神经网络初始化训得快不快"），要在一个大到穷举不完、还很有结构的可能空间里，搜出最好的那个。这个可能空间，论文叫 open-ended hypothesis space（开放式假设空间）。把这三个词拆到底：

  • 假设空间 = 所有候选答案摆在一起的那个集合。搜分子，它就是"所有能合法画出来的分子结构"；搜蛋白质，就是"所有氨基酸排列"；搜程序，就是"所有能写出来的代码"。
  • 开放式 = 这个集合大到你这辈子数不完，而且没有边界——永远能再造一个新的没人见过的候选。类比：像"所有可能的乐高搭法"，无穷无尽。
  • 有结构 = 它不是一锅随机噪声，好东西附近往往还有好东西，差一点点的改动可能让结果天差地别。所以瞎猜不行，得有章法地搜。

2｜困境

撞的墙是：真实的"验证一个候选到底好不好"这件事，又贵又慢。

做一次湿实验测抗体结合、跑一次完整训练看收敛速度——每验一个候选都要花真金白银和大把时间。于是你根本没法把空间里的候选一个个都试过去，你的"真实测试"次数是被严格限量的。这就逼出一个要命的问题：下一枪，到底打向哪个候选? 打错了就白烧一次昂贵预算。解不好，发现效率就低到没法用。

3｜旧路

之前有两条路，各有各的死穴。

旧路 A：让大模型自己反思（LLM-only reflection）。 就是让 LLM 生成一批候选，再让它自己看着结果"反思、改进、再生成"，一圈圈迭代。听着聪明，但有个隐藏的坑：LLM 对自己点子的好坏判断、对自己有多确定的判断，都不可靠——尤其对它没见过的新点子。 原文点破："LLMs generate diverse candidates but lack uncertainty quantification to guide search toward high-value regions"（大模型能生成五花八门的候选，却没有"不确定性量化"这把尺来把搜索引向高价值区域）。说人话：它经常对一个其实很糟的新点子拍胸脯说"这个行"，于是反复在原地打转、重复采样、错过真正的好矿脉。

旧路 B：经典 Bayesian optimization（贝叶斯优化，简称 BO）。 这是统计学里搜昂贵目标的老武器，原理很对——它会训一个"替身打分器"，不但猜每个候选多好，还给出"我对这个猜测有多确定"，然后专挑"可能好、而且我还没底"的地方去试。问题是它的经典实现（用 Gaussian process 高斯过程当替身）扛不住又大又有结构的空间：分子、程序这种候选没法简单塞进它的数学框架，维度一高就跑不动。原文："Standard BO struggles with high-dimensional design spaces and expensive likelihoods"（标准 BO 在高维设计空间和昂贵似然面前吃力）。

一句话总结旧路的两难：LLM 会生成、但不会判断自己的不确定；BO 会判断不确定、但生成不了复杂候选。 一个有嘴没脑，一个有脑没嘴。

4｜转折

作者的关键一转：把这两个残废各取所长，缝成一个整体。

让 LLM 当"生成器"（它天生就擅长在分子、程序这种大而有结构的空间里造候选、改候选）；另配一个Bayesian non-parametric reward surrogate model（贝叶斯非参数奖励代理模型）当"评估脑"，专门补上 LLM 缺的那块——校准过的不确定性。这个又长又拗口的名字，逐词拆开就很朴素：

  • surrogate（代理 / 替身打分器）：真实测试太贵，先训一个便宜的"替身"来猜每个候选大概多好，用它筛掉绝大多数，只把最值得的少数送去做真实测试。
  • reward（奖励）这里就是"候选有多好"的那个分。
  • Bayesian（贝叶斯）这个替身不只吐一个分，还吐一句"我对这个分有多大把握"。对见过很多类似东西的，它说"我挺确定"；对从没见过的新候选，它诚实说"我心里没底"。这个"心里没底"有个正式名字叫 epistemic uncertainty（认知不确定性）——因为没见过而不确定，不是因为世界本身随机。
  • non-parametric（非参数）：这个替身不提前把自己的复杂度写死，数据来得越多，它就长得越复杂、越贴合。类比：不是提前画一条固定形状的曲线硬套数据，而是让曲线随数据自己生长。

转折的内核一句话：大模型缺的不是创造力，是"知道自己有多不知道"这块自知之明——那就外接一个专门管自知之明的脑子给它。

5｜解法

整套 LDM 是一个一圈一圈转的循环（论文叫 recurrent architecture，这里的 recurrent 就是"重复转圈"，不是 RNN 那种循环神经网络）。一圈是这样的：

  1. 提议把"发现记忆"里目前最好的几个候选摆给 LLM 看，让它照着这些已验证好用的方向，生成一批新的候选变体。
  2. 打分 + 报不确定替身评估脑给每个新候选算两个数——预测的好坏分，和"我对这个分多没底"。
  3. 算"该不该试"的分这是全篇的心脏，叫 acquisition / uncertainty-aware value（该试哪个的评分规则）。它不是只看预测分，而是 "预测分 + 一个'这里我没底、可能藏着惊喜'的加分"（形式上就是 值 = 预测奖励 + β × 不确定性）。这正是"探索 vs 利用"的权衡：
    • 只挑预测分最高的（利用）→ 会早早卡死在一个小山头，因为模型只敢在它熟的地方转。
    • 给"我没底但可能好"的地方加分（探索）→ 才敢翻过熟悉的山头，去够那些没人踩过、可能更高的峰。
  4. 真测按这个分排序，只把最值得的少数几个，送去做那个又贵又慢的真实测试（湿实验/完整训练），拿到货真价实的结果。
  5. 记 + 学把新的好候选和真实分数塞进发现记忆（discovery memory，一个不断更新的小本子，记着到目前为止最好的候选和分数）；同时拿这条新的真实观测去更新替身评估脑，让它下一圈猜得更准、"没底"的判断更靠谱。
  6. 回到第 1 步，转下一圈。

关键设计理由：发现记忆和替身脑是"每来一个新的真实观测就更新"的（原文：discovery memory 与 surrogate "continually updated as each new experimental observation arrives"）。也就是说，它边搜边学，越搜越懂这个空间长什么样、哪儿还没探、哪儿藏着好东西。整台机器是把"经典贝叶斯优化那套有原则的探索"，第一次稳稳架到了"LLM 能生成复杂候选"的肩膀上。

6｜结局

解出来，世界变了这些样（以下都是论文摘要里逐字给的硬数，是三个不同领域、和"只让 LLM 反思"或"传统统计搜索"这两类基线比）：

  • 神经网络训练（搜"怎么设置能训得又快又好"）：把 validation BPB 往下压的幅度，是基线的 2.4 倍。拆一下 BPB（bits per byte，每字节比特数）：它是衡量语言模型训得好不好的一把尺 = 模型对每一字节文本"有多惊讶"，越低说明越会预测下一段文字、训得越好。"2.4× 的下降幅度" = 同样的评估预算下，LDM 把这个惊讶度往下压得比基线狠 2.4 倍。
  • 抗体设计（搜"哪条抗体序列抓目标抓得最紧"）：binding energy 相对降低 18.2%。binding energy（结合能） = 抗体抓住目标（比如病毒表面某个点）抓得多紧，越低（越负）抓得越牢、越可能成药。降 18.2% = 抓得比最好的旧方法紧了近两成。
  • 分子优化（同时优化溶解度、成药性等好几个互相打架的目标）：多目标综合表现相对提升 60% 以上。

最反直觉、也最值得记的那颗副发现作者发现，如果去掉那个"不确定性加分"、改成纯挑预测分最高的候选，机器反而更快陷进一个浅浅的小山头出不来。也就是说——在发现这件事上，"我不确定、去看看"比"我觉得这个最好、就它了"更重要。凭空的自信是发现的敌人；诚实的"没底"反而是把你带向新大陆的指南针。这颗种子直接解释了为什么"只让 LLM 反思"（旧路 A）会原地打转：它太自信，从不给自己留"我可能错、该去探探别处"的余地。

7｜内核

给大模型外接一个"知道自己有多没底"的评估脑，它就从一个'会生成'的嘴，变成一台'会发现'的引擎。 发现的瓶颈从来不是缺点子，而是缺一个能诚实告诉你"这个方向我心里有没有底、值不值得下注一次昂贵测试"的指南针——LDM 把这根指南针，第一次稳稳装到了 LLM 身上。

来龙去脉（倒读 3 层）

第 1 层——它直接改的是谁。 一手批"只让 LLM 反思/自评"这条路（propose-refine 自迭代，毛病是 LLM 对自己不确定的判断不可信）；一手接"经典贝叶斯优化 BO"（高斯过程 + expected improvement，原则对但扛不住分子/程序这种大而有结构的空间）。LDM = 把 BO 的"有原则地探索未知"嫁到 LLM 的"能生成复杂候选"上，让两个残废合成一个整体。

第 2 层——它站在哪条大线上。 这是"把 AI 变成发现/搜索引擎"这条线。旁边站着两拨人：evolutionary search（遗传算法、CMA-ES）——给的是无导向的多样性（会乱变异，但不会学着往好处变）；以及 AI4Science 那一脉（AlphaFold → 生成式分子/蛋白设计）。这条线上所有人反复撞的同一堵墙是：在astronomically 大的空间里，昂贵的验证预算到底该花在哪。 LDM 的答卷是：用校准过的不确定性当分配预算的准绳。它和台账里的自主研究智能体是互补的——[[2026-06-12--arbor-htr|Arbor]]（假设树让科研智能体越做越懂）、[[2026-07-27--arex-rsi-deep-research|AREX]]（会自己审自己、抓"发现难验证易"不对称的递归自改进研究员）是在流程/智能体编排层做文章；LDM 是在模型核心机制层做文章——补上"模型不知道自己不知道"这个根子毛病。

第 3 层——根在哪。 根是决策论里最老的两个问题：explore-vs-exploit（探索还是利用），和 calibrated uncertainty（校准的不确定性）——从 multi-armed bandit（多臂老虎机：面前一排老虎机，钱有限，是继续拉那台已知回报不错的，还是去试试没拉过、可能更好也可能更差的）到 active learning（主动学习：标注预算有限，机器主动挑"最该问人"的样本去标）都在问同一件事。LDM 的独家贡献，是把校准的认知不确定性第一次带给了 LLM 生成器，让"生成→判断→下注"这整个闭环，终于有了一根值得信的指南针。它也和台账的自进化/验证档（[[2026-06-09--openskill|OpenSkill]] 自造验证锚点、[[2026-07-27--arex-rsi-deep-research|AREX]] 验证级递归自改进）呼应：大家都在补"AI 怎么在没有现成答案时判断自己做得对不对"这一课，LDM 补的是其中最底层的一环——校准的不确定性。

对思染：模型进化 & 怎么用

这一步，模型往哪进化了

从"会回答"迈向"会发现"。 前沿的重心正在从"把已知问题答得更漂亮"，挪到"在人看不完的巨大空间里，主动搜出人和老办法都找不到的好东西"。而卡住这条路最硬的那块石头——模型对没见过的新候选，不知道自己有多不确定——正是 LDM 这一篇撬动的。记住这个坐标：发现能力的瓶颈不是生成力，是校准的自知之明。 以后看 AI4Science、看 AlphaEvolve 式的算法发现、看自主研究智能体，都可以用这把尺去量：它是不是解决了"模型怎么知道自己该往哪下注"。

能怎么用（提示词 & 京小贝）

  1. "生成器 + 校准过的批判器"是可直接搬的架构模式。 LDM 的第一原理是：别让同一个 LLM 既出结论、又给自己的结论打包票——它对自己没见过的情况经常胡乱自信。对京小贝这类信贷风控：当 LLM 说"这个申请人能批"时，那份自信恰恰是 LDM 警告的"不可信自评"。正解是外挂一个独立的、会报告'我有多确定'的评估器/校准分，别只看结论看信心。（这一点和台账 [[2026-07-27--arex-rsi-deep-research|AREX]] 的"模型自评置信度可信度需要单独校准"是同一道理的两面。）
  1. 不确定性 → 分流。 把"我有多没底"这个信号做成一道分诊闸门：高置信直出、中置信再补一轮材料或调更强模型、低置信转人工。金融场景里答错很贵，这道基于"模型对自己有多确定"的安全阀，是一道便宜又硬的护栏。
  1. 昂贵评估预算的分配律——花在"可能好 + 我没底"的地方。 人工复审、真实放款、线上 A/B，全是又贵又慢的"真实测试"，预算天然有限。LDM 的心法直接可迁移：别把这些贵测试浪费在你已经很确定的样本上，集中砸到"既可能高价值、又心里没底"的地方——那里才藏着你现在还看不见的收益/风险。这是任何"贵测试预算有限"的产品都适用的资源分配原则。
  1. 提示词层的小手势：给模型留"我可能错"的余地。 那颗反直觉副发现（纯挑最自信的答案反而陷进浅坑）提醒：一味让模型"给我一个最确定的答案"，会让它在自己熟的小山头里打转、错过更好解。在需要探索/找方案的任务里，显式让它列出几个候选并各自标注把握程度、点出自己最没底的地方，往往比逼它"直接给最优解"更容易翻过山头。
