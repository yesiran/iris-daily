推荐理由

为什么今天选它。"多轮长程规划"——让模型连着走十几二十步、每一步都改变局面、最后才见分晓——是当下所有 agent（智能体）产品卡住的那道墙：单轮回答已经很强，可一旦要它跨很多步把一件事办到底，它就容易在半路上跑偏、越走越错。这篇论文没有去刷任何榜，而是干了一件更底层的事：造了一个完全受控的合成小世界，把"长程规划这个本事到底是在哪一步、靠什么长出来的"从预训练一路拆到后训练，逐段做了对照实验。 它回答的是机理问题，正是思染要的那种"手感"——不是"模型又强了多少分",而是"它凭什么能连着走这么多步不散架、我该怎么喂它/怎么提示它"。

命中的质量信号（诚实版）。（1）机理导向、非刷分：它的贡献是一批可复现的因果结论，不是 SOTA 高了零点几；（2）机构过硬——中科院自动化所刘康、赵军组，国内做知识计算/信息抽取/推理的老牌强组；（3）HuggingFace Daily Papers 上榜但票数偏低（约 22 赞）——这是一篇"机理类"论文的典型待遇，它不炫模型、不放 demo，社区投票天然冷淡，但方向（长程规划）是绝对的前沿主干道。引用数在这里没意义（发表 3 天），我按方向价值和证据质量选，不按热度。

对思染的价值。这篇几乎每一条结论都能直接翻译成京小贝多轮 agent 的设计动作和你的提示词写法——尤其"让模型显式写出状态怎么变"这一招，在长任务上把成绩抬了 45.8%，是可以今天就试的提示词杠杆。

七拍故事

1. 主角 — 一个"必须连着走很多步"的模型

主角是一个要当 agent（智能体，能自己连着做很多步事、每步都要看当前局面再决定下一步的模型） 的大模型。它面对的不是"回答一个问题"这种一锤子买卖，而是"办成一件要十几步的事"：查资料→筛→再查→综合→下判断，或者在一个界面里点来点去把一个任务做到底。每一步它做的动作都会改变局面，下一步得基于改完的新局面接着来。

2. 困境 — 会做每一个动作，却走不完一整条长路

墙在这里：模型把每一个"单步动作"都学会了，可一旦要把这些单步串成一条十几步的长链，它就散架。 论文里最扎眼的一个数字——如果训练时只喂它"1 到 5 步的短任务"，它在短任务上能做到 pass@8 达 93.12%（pass@8＝让它独立试 8 次、只要有一次做对就算过，这里 93% 就是几乎题题能做出来），可同一个模型换到"6 到 8 步的中长任务"，成绩掉到 0.83%；换到"9 步以上的长任务"，直接 0.00%。

不是它不会那些动作——每个动作单看它都会。是把动作拼成没见过的长流程这件事，它彻底不会。而且长任务上还有个更狠的毛病：早一步走错，错会顺着后面十几步滚雪球，滚到最后无可挽回。这就是长程规划真正的难点——不在"会不会做每一步"，在"能不能连着走很多步不跑偏"。

3. 旧路 — 拿一堆网上爬来的、看不清也管不住的数据硬训

以前大家怎么办这个能力？靠规模：拿海量互联网数据训一个大模型，指望长程规划这个本事在里面自己涌现出来。问题是这批数据又脏又不透明——你不知道里面到底有多少长链条的例子、有多少是走了弯路的次优演示、格式是什么样。于是你训出来一个会规划的模型，却完全说不清它是靠数据里的哪种成分、在哪个训练阶段学会规划的。说不清，就没法针对性地改进——只能继续加数据、碰运气。

4. 转折 — 别在野地里猜，造一个能拧旋钮的"实验室世界"

作者的转念很朴素：既然真实数据看不清也管不住，那就自己造一个能完全控制的小世界，在里面把变量一个一个拧着做对照——就像化学家不在野外的浑水里做实验，而是在干净的试管里、一次只变一个条件。

这个小世界是三个"合成手工树"（论文里叫奇幻炼金 Fantasy Alchemy、畜牧养殖 Livestock Farming、电子组装 Electronic Assembly）：每个世界都是一棵树——底层是原料，把几样原料按规则合起来得到中间件，中间件再合起来得到更高一层的东西，一层层往上直到目标成品。树有多高（要几层）、每层多少类、每类多少个具体物件，全是作者手拧的旋钮。要几步能造出目标，也就精确可控：短（1–5 步）、中（6–8 步）、长（9 步以上）。

有了这个能拧旋钮的世界，"长程规划从哪长出来"这个问题就能被逐段做对照实验了：喂什么格式的数据、长短比例怎么配、数据干不干净、用哪种后训练方法——每一项单独拧，看结果怎么变。

5. 解法 — 三段拆开：预训练怎么长、后训练怎么塑、多来源怎么融

第一段：预训练阶段——能力是怎么"长出来"的。 三个发现：

  • 让模型显式写出"状态怎么变"，长程能力猛涨。 对照两种训练：一种让模型直接吐动作；另一种逼它在动手前先写一段"世界账本"——先认清目标属于哪一类、要凑齐哪些前置件、手里现有什么，再决定这一步动作。论文把后者叫 explicit world model construction through CoT state transition modeling，拆开就是：让模型用一段思考（CoT，chain-of-thought，模型动手前把推理过程一句一句写出来）把"我现在手里有 A、B，合起来会变出 C，于是局面从 {A,B} 变成 {C}"这种状态转移明明白白写清楚，再走下一步。效果——短任务只多 +9.4%（89.5%→98.9%），中任务多 +39.3%，长任务多 +45.8%（avg@8，即 8 次尝试的平均成绩）。任务越长，"先把状态写清楚再动手"这一招越值钱。 道理很直白：不把当前局面外化出来，走到第七步它早忘了第二步把什么变成了什么；写出来，等于随身带着一张不断更新的账本。
  • 光会"单个动作"拼不出长流程，得让它真见过长链条。 前面那个"只喂短任务→长任务 0.00%"就是证据：原子技能（atomic skills，单个孤立的动作本领）足够多，也换不来把它们拼成长流程的能力。 但补救成本极低——只要往训练数据里掺 5% 的长链条轨迹，中任务的 pass@8 就从 0.83% 跳到 51.88%。不是要海量长数据，是要一点点、但必须真见过"从头串到尾"长什么样。
  • 走了弯路的次优数据，对长任务是毒药。 把训练数据配成"4 份最优 : 8 份次优（走了弯路但也到了终点的演示）",短任务还撑得住，中、长任务直接塌到接近 0。原因就是第 2 拍说的滚雪球——长链条里早期的错误会一路放大，你喂它带瑕疵的示范，等于教它在起点就埋下会滚大的雷。短任务链条短，雷还没滚大就到终点了；长任务，必炸。

第二段：后训练阶段——能力是怎么被"塑形"的。 这里对照两种后训练（预训练之后再调教模型的手段）：

  • GRPO（Group Relative Policy Optimization，一种强化学习法）：让模型对同一道题自己试很多遍，只看最后成没成给个分，成的那批往上抬、败的那批往下压（Group＝一组答案放一起比、Relative＝互相比高低、Policy Optimization＝据此调整它的行为倾向）。
  • OPD（On-Policy Distillation，在线策略蒸馏）：请一个更强的老师，盯着学生自己走出来的每一步，逐个词地告诉它这一步的分布该往哪调（On-Policy＝在学生自己走的路上教、而不是拿老师的完美答案硬灌；Distillation＝把老师的判断一点点蒸给学生）。

核心结论用一个叫互信息（mutual information，衡量两件事绑得多紧的量）的工具切出来：后训练存在三块区域——

  1. "不必要"区那些"这道题专属、换道题就没用"的具体知识（高互信息）。后训练每次只能小幅挪动参数，硬灌这类专属知识灌不进去，白费劲。
  2. "有效"区那些"到处都通用的规划套路"（低互信息）。这类套路模型其实预训练时已经隐约有了，后训练能把它激发、点亮，泛化到更多题上——这是后训练真正该发力的地方。
  3. "不支持"区GRPO 在长任务上落在这里。因为它只在最后给一个成/败信号，链条一长，它根本分不清是哪一步的功劳或过错（这就是 credit assignment，功过分配问题——走完一长串只拿到一个总分，怎么把功劳和责任落到具体某一步上）。分不清，给出的参数更新方向就忽左忽右、自相矛盾，越长越乱。

而 OPD 的"有效区"比 GRPO 宽得多：因为老师是逐词给方向的，不用等到最后才打分，方向一致、稳定。最能说明问题的对照——在被次优数据污染过的预训练底子上跑长任务，OPD 能把成绩拉到约 73%（avg@8），GRPO 只有约 41%，三十多个点的差距。（不同设定下具体数字有浮动，比如另一设定是 OPD 78.5% 对 GRPO 64.2%，但"长程且数据不干净时 OPD 明显更稳"这个方向是一致的。）一句话：任务越长、数据越脏，"逐步密集地教"就越比"最后打个总分"靠谱。

第三段：多来源整合——本事怎么"融"到一起。 现实里你常要把好几个环境、好几个老师的本事融进一个模型。作者用 MOPD（Multi-teacher On-Policy Distillation，多老师在线策略蒸馏，同时请几个各自擅长一个环境的老师教一个学生）测了三种情形：

  • 规划套路彼此兼容 → 一个环境里练出的本事能迁移到没见过的新环境，打破环境边界；
  • 套路部分重叠 → 模型能一边学新的、一边不严重忘掉旧的，这正是持续学习（continual learning，不断学新任务又不遗忘旧任务）想要的；
  • 套路彻底冲突 → 学生为了迎合新老师把旧本事灾难性地忘光（catastrophic forgetting），互相干扰、两头落空。

也就是说：能不能把多来源的本事融到一起，取决于它们底层的"规划套路"是否共享同一套骨架。共享，就能迁移、能持续学；冲突，就会互相拆台。

6. 结局 — 长程规划的"配方表"第一次被写清楚

跑完这一整套对照，长程规划这个曾经"只能靠规模碰运气"的能力，第一次有了一张可操作的配方表：想让模型连着走很多步不跑偏，(1) 预训练就要逼它显式写出状态转移（长任务 +45.8%）；(2) 数据里必须掺一点真的长链条（5% 就够，短任务再多也换不来）；(3) 数据要干净，次优演示对长任务是毒药；(4) 后训练在长程、脏数据下优先用逐步密集监督的 OPD 而非只看结果的 GRPO；(5) 想融合多来源本事，先看它们的规划套路兼不兼容。

最反直觉的那颗副发现：决定长程成败的，往往不是"模型见没见过更多动作"，而是"它心里那张状态账本清不清楚、以及有没有人逐步纠着它别在早期跑偏"。 换句话说——瓶颈从"它看见了什么（感知/知识）"挪到了"它想得清不清楚、走得稳不稳（推理与过程）"。

7. 内核 — 长程能力是"过程的干净度",不是"动作的丰富度"

带走这一句：一个模型能不能把一件长事办到底，不取决于它会多少花招，取决于它有没有一张随身更新的状态账本、以及训练时有没有人陪它把每一步走稳。 会做每一步 ≠ 走得完整条路；长程的胜负手在"过程的干净度"，不在"动作的丰富度"。

来龙去脉（倒读溯源）

第一层——它在改进谁。 直接对话的是两条后训练主线：一条是 GRPO 那一脉的"只看结果的强化学习"（DeepSeek-R1 时代把"自己试很多遍、成的抬败的压"推成了推理训练的主流）；另一条是近一年热起来的 on-policy distillation（在线策略蒸馏）——本台账 [[2026-07-15--weak-to-strong-direct-opd]]（Direct-OPD，弱到强的在线蒸馏）、[[2026-07-18--seed-self-evolving-opd]]（SEED 自进化在线蒸馏）都在这条线上。这篇的新意是：第一次把这两条路放到"长程规划"这个显微镜下对照，指出 GRPO 的病根是长链条里的功过分配失灵，而逐步密集的 OPD 正好补这个洞。

第二层——它属于哪个研究纲领。 它是"把某个能力从预训练一路拆到后训练"这个纲领的一员。它的直接姊妹篇就在本台账里——[[2026-07-22--pretrain-to-rl-reasoning]]（《从预训练到后训练理解推理》）拆的是单轮推理（一口气想清一道题）；这篇拆的是多轮长程规划（连着走很多步办成一件事）。前沿的关注点正从"一口气想得对不对"，挪到"连着走得稳不稳"——这篇是那条主线往 agent 方向迈的一步。而"让模型显式写世界账本"这一招，又接着 [[2026-07-03--orca-world-foundation-model]]（Orca：世界在你脑中）、[[2026-06-19--kairos-world-model]]（Kairos 世界模型）那条"让模型内建一个会算的世界模型"的暗线——只不过这里的世界模型不是用来生成视频，而是用来在长链条里记住局面怎么变。

第三层——根在哪。 根是强化学习里一个几十年的老问题：长程信用分配（temporal credit assignment）——一件事要做很多步、最后才知道成败，你怎么知道到底是哪一步做对/做错了、该奖励/惩罚哪一步。这个老问题如今原封不动地砸到了 LLM agent 头上：链条一长、只有最后一个成败信号，模型就学不明白。这篇给出的答案是——别只靠最后那个稀疏信号（GRPO），让一个老师逐步把方向补密（OPD）；以及在数据侧，别指望规模自动涌现，把"该见的长链条、该写的状态账本、该有的数据干净度"直接配进去。

对思染：模型进化 & 怎么用

模型进化逻辑往哪挪了一步

前沿的瓶颈正在从"单轮想得对不对"转到"多轮走得稳不稳"。单轮推理这两年已经被 RL 推得很强，可"连着走十几步把一件事办到底"仍是所有 agent 产品的真正天花板。这篇的意义是：它把这道墙从玄学变成了工程——长程能力不再是"喂够数据就自己涌现"的运气，而是一张可以照着配的配方表（写状态、掺长链、保干净、长程用 OPD、融合看套路兼不兼容）。对你判断"agent 什么时候能真正可靠地跑长任务"，这比任何一个跑分都更能给手感：谁把这几条配方吃透，谁的 agent 才走得远。

能怎么用（提示词 + 京小贝产品判断）

  1. 提示词最直接的一招：逼模型"先写状态账本，再动手"。 论文里"显式写状态转移"在长任务上 +45.8%——这不用等训练，你今天就能在京小贝的多轮 agent 提示里加一条：每走一步前，先用一两句话复述"我现在掌握了什么、上一步把什么变成了什么、离目标还差哪几件",再决定这一步做什么。 相当于强制它随身带一张不断更新的账本，走到第八步不会忘了第二步干了啥。多轮理财对话、多步骤查询-核对-下结论的场景尤其受用。
  1. 早期错误会滚雪球——把校验点前移。 长链条里第一步的错会一路放大到无可挽回。产品含义：京小贝的多轮 agent 别让它一口气跑十几步再回头看，要在前几步就设校验闸（确认它对用户意图、对关键事实的理解没歪），早发现早拽回来。这和你之前记下的 AREX"逐条自查+只补没证实那条"是一路的——[[2026-07-27--arex-rsi-deep-research]]——早验、勤验，比事后兜底便宜得多。
  1. 训 / 微调 agent 时的数据律：少量真长链 + 干净，胜过海量短样 + 带瑕疵。 如果你们要 SFT 或蒸馏出一个跑长流程的京小贝 agent——(a) 训练集里必须真掺进"从头串到尾"的长轨迹（哪怕只占 5%），光堆单步/短样换不来长程能力；(b) 宁可少而干净，别多而带弯路，次优演示对长任务是毒药。这条直接指导你们的数据采集与清洗优先级。
  1. 后训练方法选型：长程、脏数据场景优先"逐步密集监督"（OPD 型），别只靠"结果奖励"（GRPO 型）。 金融多轮场景链条长、真实数据往往不干净，正是 GRPO 信用分配失灵、OPD 明显更稳的区间。若你们在做 agent 的后训练，方法选择上这是一条有据可依的默认倾向。
  1. 多能力融合看"套路兼不兼容"。 想把"财富问答 + 保险 + 信贷"几套 agent 本事融进一个模型，能不能不打架，取决于它们底层规划套路是否共享骨架。兼容→能迁移能持续学；冲突→会灾难性遗忘、两头落空。上新能力前先评估它和存量能力的套路冲不冲突，别默认加了就有、加了不忘。

一句护栏： 这套结论是在三个合成的手工树世界里做出来的——干净、可控，但比真实网页/工具环境简单得多。方向和机理可信，但"5%""45.8%"这些具体数字别当成真实业务里的保证值，要在你自己的场景里 A/B 复验。合成世界证的是"该往哪拧旋钮",不是"拧到几度"。
