推荐理由

  1. 它把一个刚开的新范式从"能不能编译"推进到"编译得好不好"：07-04 台账的 PAW（Program-as-Weights，程序即权重）第一次把"提示词编译成一次成型、终身本地免费运行的神经工件"这根轴立了起来——但那是个只有一档的编译器：一次前向传播、几秒钟出结果，遇到真正难的模糊函数就编出个基本不能用的废件（在难例子集 FuzzyBench-Hard 上一个精确匹配都没有、语义准确率仅 22.4%）。今天这篇（同一个 Yuntian Deng 组）给这台编译器装上了"优化档"：难的规格就多花编译时算力，让教师模型现造训练样本、再真刀真枪训练那片适配器，语义准确率直接抬到 83.6%。追前沿追的就是看一条线怎么长——PAW 立轴、这篇把轴变成了一根可调的"速度↔质量"旋钮。
  2. 信号扎实HuggingFace Daily Papers 当窗口第一名，207 赞（当日榜上最高、约为第 3 名的 1.3 倍）；作者滑铁卢大学 Yuntian Deng（以"把思维链内化进隐层"系列知名，也是 06-08 Code2LoRA 和 07-04 PAW 的通讯）＋哈佛 Stuart Shieber（计算语言学老教授、Deng 的博导）；论文已把编译器挂成一个公开可交互的在线服务。发表 2 天，Semantic Scholar 引用≈0（正常，且今天 429 限流未取证——不靠引用数选片）。
  3. 对思染直接命中京小贝管线里那批"按 token 付费的模糊小函数"（意图分类、工单路由、格式修复、query 改写、日志告警），PAW 给的是"快但飘"的编译路，这篇给的是为真正要紧的那些函数准备的"-O2 优化路"——花一分钟编译时算力，把难函数编成能用（83.6%）、能冻结、能版本管理的本地工件。而且它揭示了一条对写提示词/造数据都有用的规律：编译质量 = 你的规格质量 + 教师造的示例质量；教师配置也有讲究——纯用弱教师(GPT-5.4-mini)造数据仅 0.746，掺入约三分之一强教师(GPT-5.5)样本后跳到 0.851（论文没有报告"纯用强教师"这一档对照，严格说只证明了"混合≫纯弱"，还不能断言"混合＞纯强"，下文如实标注）。

七拍故事

一拍 · 主角

主角是一批"编不出来"的规格。上一篇 PAW 里，开发者用一句自然语言写下一个模糊函数的规格（"把这段格式坏掉的地址标准化""判断这条日志要不要报警"），PAW 的编译器一次前向传播就把它翻译成一小片 LoRA 权重（先拆词：LoRA＝Low-Rank Adaptation，低秩适配，给冻结模型外挂的一小片可插拔"补丁参数"，运行时把补丁输出加到原模型上从而改变行为，因为用两张窄表相乘代替一张大表，所以小到能当文件传），挂到一个 6 亿参数的小解释器上就能永久本地运行。大部分规格这样就够了。但总有一批规格——逻辑绕、边角多、一句话根本说不周全——快编译器编出来的工件基本是废的。这批"难规格"就是本篇的主角。

二拍 · 困境

难在哪、利害在哪？作者把 PAW 处理不好的那些规格单独拎出来，组成一个难例子集 FuzzyBench-Hard（定义就是"快编译器 PAW 在上面一个精确匹配都产不出"的那部分规格）。快编译器在这个子集上的语义准确率只有 22.4%——五次里错四次。也就是说，PAW 立起来的"编译一次、终身本地跑"这个漂亮范式，对恰恰最需要它的那批硬骨头函数，交付的是一个能装、能跑、但答案基本不对的空壳。范式有了，但天花板卡在"简单的能编、难的编成废件"这道坎上。解不了它，"提示词有编译器"这句话就只对简单函数成立。

三拍 · 旧路

绕开这道坎，此前只有两条都不痛快的路。第一条：认命继续调远程大模型——每个输入都发一趟 API 请求。这正是 PAW 一开始要消灭的四笔烂账：贵（按 token 计费）、慢且断网即死、行为不可复现（供应商静默升级导致线上行为漂移）、软件不再自包含。第二条：给这个难函数单独做一次完整微调——行为能固化，但你手上根本没有这个函数的训练数据（模糊函数的定义就是写不出规则、也没现成标注），而且为"修一种地址格式"单独收数据、开 GPU、调超参，把一个"函数"硬生生变成一个"项目"，成本高到没人干。一条太贵太飘，一条门槛太高，难规格就这么悬着。

四拍 · 转折

作者的关键一转：编译器凭什么只能有一档速度？ 现实里的编译器（比如 gcc）都有优化开关——-O0 图快、不做优化，-O2 慢一点但把代码优化到能用。PAW 那台"一次前向传播出 LoRA"的快编译器，本质是 -O0：摊销（amortize，把每次都要付的钱改成一次性预付）到极致、几秒出件，但不为任何单个规格额外花力气。那难规格就走 -O2：在编译时多投入算力，专门为这一个规格现造训练数据、再把适配器真正训一遍。花钱的重活仍然全压在"编译一次"里，日常运行照样本地、免费、离线——只是这一次的编译，从"3.5 秒的一次前向"变成"50.9 秒的一轮训练"。用一分钟编译时间，换一个真能用的函数。

五拍 · 解法

系统叫 compile by training（编译即训练），它和 PAW 共用同一套运行时（同一个解释器、同一种程序格式、同一个调用接口），只把"编译"这一步换成一轮真训练。三个零件：

  • 紧凑解释器（compact interpreter）：一个冻结不动的 Qwen3-0.6B（通义千问最小档，6 亿参数），所有编译出来的函数共用这一个底座——像一个 CPU 跑无限多个软件。
  • 适配器（adapter）每个规格一片自己的 LoRA（秩 rank-64、alpha-16）。这片 LoRA 加上一段编译器生成的提示词脚手架，就是这个规格编译出来的完整"程序"。
  • 编译时怎么训（本篇的核心动作）① 教师造数据——把自然语言规格交给教师模型，让它们照规格现编出一批结构化的（输入, 输出）JSON 样本，作为这个函数的合成训练集（模糊函数没有现成标注，就让强模型当场造）；关键发现之一：教师配置有讲究——同等规模(3600条)下，纯用弱教师(GPT-5.4-mini 单独造全部样本)语义准确率（论文记作 LEM——用模型判断输出与标准答案语义是否一致、不苛求逐字相同）只有 0.746；换成 GPT-5.4-mini 和 GPT-5.5 按 2:1 混合供给监督后跳到 0.851（论文没有报告"纯用强教师 GPT-5.5"这一档对照数字，严格说这证明的是"混入强教师样本比纯弱教师好"，还不能断言"混合比纯用强教师更好"）。② 暖启动——不从零开始，直接拿 PAW 快编译器那一次前向传播预测出的 LoRA 当训练起点（"uses the amortized prediction as a starting point"），再在合成数据上继续优化。③ 专属优化——就在这个规格的合成样本上训练这片 LoRA，把纯文字给不了的细粒度行为压进权重里。训完，这片 LoRA＋脚手架就是一个可存储、可版本管理、可像普通软件一样组合调用的本地神经函数，运行时甩掉所有教师、零 API。

六拍 · 结局

  • 主结果在快编译器全军覆没的 FuzzyBench-Hard 上，编译即训练拿到 83.6% 语义准确率，对比 PAW 快编译器的 22.4%——绝对高出 0.612（61 个百分点）。那批"能装能跑但答案不对"的空壳，现在真能用了。
  • 代价明码标价这份准确率来自更贵的编译时间——50.9 秒（B300 GPU 上）对快编译器的 3.5 秒。这正是范式的核心卖点：把一分钟砸在"编译一次"里，换来的函数此后终身本地、免费、离线运行，均摊到成千上万次调用后每次近乎零成本。
  • 数据规模的账合成样本从 1440 条（LEM 0.821）加到 2400 条（0.836）后先撞平台期（3600 条仍 0.836），一直堆到 7200 条才又跳到 0.866——不是线性给钱线性涨，中间有一段花钱不见效的平台，堆够量才再上一个台阶。
  • 落地是真的编译器已挂成一个公开可交互的在线服务；三个演示——一个能跨多站点操作的网页助手、一个用自然语言控制的 3D 虚拟形象、一个英语↔"Claudish"（Claude 内部行话，作者的彩蛋）双向翻译器——都是由编译出来的函数直接驱动的。
  • 一处需要诚实标注的发现论文只报告了两档教师配置的对照——纯用弱教师(GPT-5.4-mini 单独造全部 3600 条样本)语义准确率 0.746；换成弱强按 2:1 混合(2400 条 mini + 1200 条 GPT-5.5)后跳到 0.851。这证明"掺入强教师样本比纯弱教师好"；但论文没有报告"纯用强教师 GPT-5.5 单独造全部样本"这一档，所以还不能像直觉推断那样断言"教师队伍多样≫单一最强"——这条更强的说法目前缺证据，是完整版写完后经二次核验发现的边界，如实标注，不隐藏。
  • 诚实交底① 合成监督会继承教师的错——教师造的样本本身可能错，编出来的函数就跟着错；论文明说"需要保证正确性的应用应当校验输出、或保留确定性的控制路径"。② 还没做系统的用户研究，真实可用性的证据有限，作者列为 future work。③ 沿用 PAW 的边界：目前主打单步函数（一进一出），且解释器与这套编译流程成对绑定。

七拍 · 内核

"把智能编译成本地工件"这个动作，从今天起有了优化档。 PAW 证明了提示词可以被编译成一次成型、可版本、可离线的神经函数；这篇证明了这台编译器不必只有一档——简单函数走"秒级、一次前向"的快档，难函数走"分钟级、教师造数据＋真训练"的优化档，二者共用同一个运行时、连成一条完整的"速度↔质量"旋钮。神经函数就此从"便宜但飘"毕业成"你付多少编译算力、它就好到多少"。软件工程里那句老话——"要快还是要好，拨一下优化开关"——第一次原样长到了神经网络身上。

来龙去脉（倒读 3 层）

第 1 层（直接前驱，同组同数据同运行时）——PAW（[[2026-07-04--paw-program-as-weights]]，Yuntian Deng 组，两个月前）：PAW 立起"程序即权重"这根轴，用一个以自然语言为输入的超网络（hypernetwork，输出不是答案而是另一个网络的权重）一次前向传播就吐出 LoRA，几秒出件、终身本地跑。它的短板是只有快这一档：对难规格（FuzzyBench-Hard）几乎失效。本篇是它的优化档孪生——同样的程序格式、同样的运行时接口、同样的 FuzzyBench，甚至直接拿 PAW 的快预测当训练起点暖启动，再投入教师合成＋专属训练把难例子救回来。一篇立轴、一篇把轴做成旋钮，是教科书式的"同一条线的下一步"。

第 2 层（两条技术根汇流）一条是"文字→权重"/超网络这条线（Hypter 2021、HINT/HyperTuning 2023、Text-to-LoRA 2025，以及本组 06-08 [[2026-06-08--code2lora]]"给代码模型生成适配器"）——这条线管"把一段描述变成一片适配器"。另一条是教师合成/蒸馏这条线——用强模型现造训练数据去教一个小模型，与台账里 07-15 [[2026-07-15--weak-to-strong-direct-opd]]、09-02 [[2026-09-02--opd-not-distillation]] 那批"用更强的老师塑造学生"的工作同源（区别是：那些是在学生自己走的轨迹上逐词给方向的 on-policy 蒸馏，这里是让教师离线造好整批带标注的合成样本再训适配器，更接近"数据蒸馏"）。本篇的新意就是把这两条根焊在编译器里：超网络负责给出快而糙的起点，教师合成＋训练负责把起点优化到能用。

第 3 层（思想根）——摊销 vs 逐例优化，以及 Software 1.0/2.0/3.0：摊销（一次性预付换终身免运行时开销）是编译器打败解释器、查找表打败重复计算的老思想，PAW 是它的极致（编译时只花一次前向）。本篇则点破：摊销不是非黑即白，而是一条连续谱——你可以在编译时多花算力做逐例优化（per-spec optimization），换更好的工件。落到 Karpathy 的三层楼（1.0 人写代码 / 2.0 训练出的权重 / 3.0 提示词）：PAW 第一个把 3.0 编译回 2.0、用 1.0 的工程文明（版本、打包、离线、可复现）管起来；本篇给这条"3.0→2.0"的编译通道补上了优化 pass，让编译出的 2.0 工件质量可控可调。

与台账暗线的咬合这是"智能价值从在线消耗转向离线固化"这条暗线的又一步深化——06-20 S-Agent、07-01 Agents-A1 把大能力捏进小模型，PAW 把粒度切到单个函数、成本压到一次前向，本篇则补上"难函数也能固化、且质量可按算力买"的最后一块。而"教师队伍混用(2:1)显著优于单一弱教师"这个结果，也算是给台账里"多样性/见世面胜过单点死磕"的规律添了一组数据点——但严格说只验证到"混合＞纯弱"，"混合＞纯强"这个更强版本目前没有直接证据支撑，暂不归入这条规律（呼应 PAW 里"编译器生成的 LoRA＞在该任务上全量微调"）。

对思染：模型进化 & 怎么用

模型进化逻辑往哪挪了一步前沿这根"能力能不能被固化成便宜工件"的坐标轴，今天多了一个刻度——固化不再是"能/不能"，而是"你愿意在编译时花多少算力，它就固化得多好"。基础模型的终局角色越来越像一个"工具车间＋质检线"：被调用一次，产出一个可复用、可分发、行为冻结的小工具；而且对难做的工具，你可以让它多花点工、造更多训练样本、把质量打上去。当"编译"从只有快档变成有优化档，大模型 API 里那部分"高频、稳定、值得固化"的流量会更彻底地永久性离开——不是被更便宜的 API 替代，是被"编译成本地工件、不再需要 API"替代。

对提示词的认知升级（最直接）这篇把一条规律钉死了——编译质量 = 规格质量 × 教师造的示例质量。教师是照着你的规格现造（输入,输出）样本来训练函数的，所以你规格里没说清的边角，教师就造不出对应样本，函数就学不会。三条可直接用的纪律：① 写规格（＝写提示词）时，一段干净的任务复述＋几个能钉住边角情况的输入输出示例，是信息密度最高的形态——PAW 已证明编译器自己都会收敛到这个格式，本篇进一步证明这些示例直接变成训练数据。② 要可靠就别光"描述"，要"给例子"，尤其把容易出错的边角案例作为示例喂进去。③ 造数据/评测集时，教师配置值得多测一档：这篇实测只验证到"2:1 弱+强 显著＞ 纯弱教师"(0.746→0.851)，没有测"纯强教师"这一档做对照，所以还不能断言"混合比单一最强模型好"——但已经证明"别怕掺弱教师"，纯用最贵的模型未必是唯一或最优选择，这条边界对思染团队评估合成训练/评测数据的教师配置策略仍有参考价值（至少省钱不吃亏）。

对京小贝的产品判断① 把管线里"按 token 付费的模糊小函数"做分档：意图识别、工单路由、格式修复、query 改写、日志告警里那些高频且稳定的，值得走"-O2 编译档"——花一分钟编译时算力换 83.6% 的难例子表现，然后冻结成本地工件（行为钉死、可审计、可复现，供应商静默升级不再让线上漂移——这对金融产品是合规刚需）。简单的走快档、难的走优化档，正好对上这篇的旋钮。② 务必配校验或确定性兜底：论文亲口说合成监督会继承教师的错，需要保证正确性的场景要么校验函数输出、要么保留一条确定性规则路径——金融场景尤其别把编译出的模糊函数当"绝对正确"，让它做初筛/建议、把最终裁决留给可审计的规则或人。③ 现在就能落的架构思路：把稳定环节从"每次调大模型"逐步迁往"编译/蒸馏成小模型工件"，大模型留给真需要现场智能的环节；这篇让"连难环节也能迁"变得可信了一截，但别急着上生产（还只做单步函数、合成数据验证中、无用户研究）。
