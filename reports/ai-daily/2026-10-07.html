Google 发布可在设备上运行的多模态向量模型

事件Google DeepMind 于 10 月 6 日公布 EmbeddingGemma 2：7.4 亿参数、Apache 2.0 许可，可把文本、代码、图像、视频和音频映射到共同向量空间，面向设备端推理。Google 称模型最高可减少 6 倍向量存储；量化后在 Pixel 11 Pro 上，纯文本约需 191MB 活跃内存，多模态版约 567MB。这些是厂商公布的数据，不是本日报独立测试。Google 官方公告

为什么重要

多模态检索若能在手机等设备上完成，部分搜索和 RAG 功能就不必将原始资料送往云端，也能减少离线场景的调用依赖。开放许可和现成部署工具降低了试用门槛；模型质量、耗电和索引成本仍需按目标设备实测，因此不能把单机内存数据直接等同于可规模化落地。

接下来观察关注设备覆盖、实际召回率与电量消耗，以及模型和向量库在真实产品中的总内存成本。

OpenAI 将合同工作流纳入代理训练和评估

事件OpenAI 于 10 月 6 日公布与合同软件公司 Ironclad 的研究合作。双方围绕法律、商业和采购流程设计 11 项任务，涵盖协议设置、审批流程和可复用条款配置；OpenAI 报告 GPT‑6 Astra 平均得分 55.0%，GPT‑5.6 Sol 为 41.6%。公司估算每次尝试平均耗时分别为 19.2 和 37.0 分钟，但明确说明这是基于假定处理速度的模拟估算，不是客户实际节省时间；任务数量也不代表全部合同工作流。OpenAI 与 Ironclad 评测说明

为什么重要

企业代理的难点不只在于会不会点界面，而在于能否把审批阈值、例外条件和结果检查贯穿多步骤。把熟悉业务的人参与定义的任务纳入训练和评估，能把产品验收从“动作完成”推向“流程规则是否满足”。但 11 项任务只是窄样本，现阶段还不能据此推断代理已能独立承担真实合同流程。

接下来观察后续公开任务是否扩展到更多软件和例外情况，以及客户部署中错误率、人工复核量和回滚能力如何。

OpenAI 向开发者开放 Decisions API 测试

事件OpenAI 的 API 更新日志记载，10 月 6 日发布 Decisions API beta，当前模型为 GPT‑6 Luna，可将文本和图像输入转换为类型化决策；公司称速度最高可达经 Responses API 调用的 10 倍。日志还记载 API 用量等级从五档简化为 Build、Launch、Grow 三档。速度比较属于 OpenAI 的产品说明，尚无本期独立基准验证。OpenAI API 更新日志

为什么重要

将分类、路由或动作选择放进专门接口，可能让产品在交互中更频繁地选择模型、工具或下一步动作，而不必每次都经过通用生成流程。这改变了开发者的编排选项，但是否降低端到端延迟或成本，取决于自身任务准确率、调用计费和失败回退；API beta 的能力边界仍应以实际文档和测试为准。

接下来观察关注选择准确率、延迟分布、计费方式和模型支持范围，尤其是错误选择后的安全回退。

Anthropic 将网络安全访问改为分层资格申请

事件Anthropic 于 10 月 6 日宣布扩展 Cyber Verification Program，将符合资格的安全团队访问先进网络能力的方案合并为三个访问层级；层级对应不同工作范围、验证要求和安全控制。公司称相关层级可开放 Claude Opus 5.5、Sonnet 5.5、Mythos 5.1 等模型，并减少部分网络安全工作中的拦截。该范围与准入条件是 Anthropic 的项目说明，不代表所有用户获得相同权限。Anthropic 项目公告

为什么重要

双重用途能力的产品交付开始从统一拦截转向按身份、任务和验证程度分层。这样可能让真实防守人员减少误拦截，同时把资格核验、用途约束和后续审查变成产品运营的一部分。能否兼顾安全与可用性，还取决于准入速度、滥用处置和误拦截数据，公告本身不足以证明治理效果。

接下来观察查看申请标准、审批时长、可执行任务边界及后续公开的误拦截与滥用处置数据。

OpenAI 扩展青少年学习工具，但核心新功能仍待开放

事件OpenAI 于 10 月 7 日发布青少年学习与升学规划说明，称 College Planner 将进入 ChatGPT for Teens，可整理申请要求、截止日期和资助信息；公告将其描述为即将推出，并未给出本期已上线的确认。文章同时介绍学习可视化、Study Mode 等既有使用情况，并公布公司自有统计。相关数据是 OpenAI 的产品使用披露，不能单独证明学习效果或安全性。OpenAI 青少年学习产品说明

为什么重要

未成年人学习产品的价值不只在新增功能，还在默认体验、适龄设计与使用边界。把计划中的规划功能与已有学习工具区分开，有助于避免把产品路线图误读为已经可用的能力。当前公告重点是功能方向和公司自报使用情况，不能据此判断外部评估、学习成效或所有地区的实际开放范围。

接下来观察College Planner 的实际开放日期、适用年龄和地区，以及后续能否看到独立评估和具体保护措施。

趋势分析Connecting the Dots
1

本地部署开始覆盖检索层，而不只是生成模型。

EmbeddingGemma 2 把多种媒体映射进同一设备端向量空间；它降低了开发者尝试本地多模态搜索的入口门槛。Google 公布的内存和存储数据仍需在更多设备上验证。下一项可观察信号是不同硬件的召回质量、索引耗时和持续运行成本。

2

企业代理的评估单位正在从动作走向流程。

OpenAI 与 Ironclad 的 11 项任务要求代理维持审批规则并验证流程结果；与普通网页操作相比，这将业务约束纳入评估。任务样本仍小，时间也为模拟估算。采购判断应等待更广任务覆盖、真实环境错误率和人工复核数据，而不是只看演示成功率。

3

能力开放逐渐带上治理条件。

Decisions API 把类型化决策单独提供给开发者；Anthropic 则按安全任务和资格分层开放网络能力。前者重在编排速度，后者重在访问控制，两者都把模型能力包装成有边界的接口。可验证的行业变化将体现在准确率、访问审批、滥用处置和失败回退，而不只是厂商给出的速度或能力描述。

4

产品宣布与实际可用需要分开管理。

OpenAI 的 College Planner 仍是即将推出；Flow Music 的插件导出则已由 Google 明确描述为可用能力。对产品决策者而言，路线图、测试开放和正式可用是不同状态，市场评估应逐项记录开放日期、用户资格和地区条件，避免把公告中的未来式功能算作当前竞争能力。
